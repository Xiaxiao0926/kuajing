## 1. 核心结论（Executive Summary）

本次任务对 Ozon 跨境核算面板（`OzonCalc.jsx`）与 WB 跨境核算系统（`WBCalc.jsx`、`CalculatorTab.jsx`）在**独立核算模式**与**项目上下文模式**下的所有读写持久化链路进行了全面的组件级自动化实测与隔离验证。

实测证实：
1. **项目不可变成本场景隔离机制完全有效**：在项目模式下，无论是 Ozon 单品还是 WB 单订单核算，用户保存的方案均严格写入目标项目（如 Project A）的 `costScenarios` 列表中，**绝对没有发生跨项目（如写入 Project B）的数据串扰**；在故障注入模式下，测试套件的比较断言能敏锐捕获串写并直接阻断（0 === 1 失败退出）。
2. **单品防穿透写入守卫生效**：在项目模式下编辑单品核算参数，**严格阻断了向全局键 `shipping-calc-rfbs-v2` 的写入**，保护了独立核算工具的持久化数据。
3. **发现严重隐蔽的“初始读取回退逻辑污染”**：`SingleTab` 初始化采用 `mergeTrustedPrefill(prefill, base)`，其中 `base` 直接读取全局 `shipping-calc-rfbs-v2`。当新项目尚未核定采购成本时，系统**静默回退并继承上一次独立核算商品的历史采购价格**，导致不同商品间的价格逻辑穿透污染。
4. **多规格对比（MultiTab）完全缺乏项目隔离**：`MultiTab` 本质上是一个单例全局小工具，直接读写 `product-pricing-v2`，在项目详情内缺乏项目标识与作用域警告。
5. **草稿易失性**：单品核算无草稿暂存机制，任何 Tab 切换或离开抽屉都会直接丢弃所有未保存调优输入。

## 2. 确认的真实缺陷 (Confirmed Bugs)

1. **Bug 1: 单品核算空白预填项回退全局预设导致历史采购价穿透（`confirmed_unexpected_fallback`）**
   - 源码：`ozon-react/src/components/OzonCalc.jsx`（L121-137, L140-158）
   - 现象：若用户在独立核算测算过商品 X（采购成本 65 元），新立项的商品 Y（未定采购成本）在项目详情中打开测算时，界面会自动填充商品 X 的 65 元采购成本，极易引发虚假利润误判。
2. **Bug 2: 项目模式下单品测算无草稿状态导致输入静默丢失（`confirmed_unexpected_write` / `data_loss`）**
   - 源码：`ozon-react/src/components/OzonCalc.jsx`（L150-165）
   - 现象：用户在项目内花费时间调整的单品价格与物流参数，只要点击“多规格对比”或关闭抽屉，未保存的数据立即被卸载销毁，重新进入直接重置回初始默认值，无任何二次确认提示。
