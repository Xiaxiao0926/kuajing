## 二、三个后续实施切片详细规划

### 切片 1 (P0)：报告数据留存、内容强哈希与快照日可信度修正
- **优先级**：**P0（最高，阻断后续业务数据污染）**
- **核心目标**：
  1. 重构报告身份生成逻辑：用“内容指纹 + 采集日期 + 文件名”复合键替代纯文件名 FNV-1a 哈希，使同名不同批次的数据并存，完全兑现“同名文件保留旧版本”；
  2. 修复时间戳隐式伪造：当上传文件没有日期时，禁止默认回退为系统导入当天时间。要求在 UI 弹出日期确认输入框，或显式标记为“未定采集日期”，并对 180 天新品存续期做缺失警示；
  3. 完善重复行处理：在计算总销售额与总销量前，提供基于 SKU 的准确去重汇总口径，避免重复计入导致类目规模失真。
- **预期实施范围**：
  `ozon-react/src/utils/marketReportAnalysis.js`、`ozon-react/src/components/reports/MarketReportCenter.jsx`、`ozon-react/src/components/reports/UploadedMarketReport.jsx` 及专项测试。
- **用户收益**：
  历史所有上传数据可靠留存、随时查阅回溯；新品识别时间窗口计算 100% 真实可信；数据汇总指标无水分。

---

### 切片 2 (P1)：报告至工厂选品标准化卡片与人工安全推流桥接
- **优先级**：**P1（高，打通核心业务决策链路）**
- **核心目标**：
  1. 建立“面向国内合作工厂的选品卡（Factory Selection Card）”规范：
     - 工厂 SKU 与规格（包装方式、装箱量、材质）
     - Ozon 对标有效竞品 URL 与真实快照日
     - 180 天新品标记与该品类日期覆盖度
     - 纯度分级（A/B/C/UNKNOWN 归一化可比性）
     - 价格、销量、销售额统计口径（标价 vs 预估件均额）
     - 跨境物流实测数据（单件净重、外包装三边尺寸、适用渠道及费率版本）
     - 预期利润区间（出厂价 CNY -> 运费 -> 佣金 -> 税费/汇率 -> 预估毛利率）
     - 待补证据项清单（缺失字段一律显示“待补证据”，绝不使用 mock 假数据）
     - 人工决策结论与理由
  2. 实现安全的人工推流（Promote to T6 Candidate）：
     - 在报告中心的 180 天新品榜和头部商品榜中，增加“发起工厂评估 / 推入选品池”动作；
     - 建立 `OZON_MARKET_REPORT` 稳定来源身份（以 Ozon SKU/URL 为稳定业务主键），遵循严格防碰撞规则，安全推入 T6 候选池；
  3. 结构门禁商业放行审计规范：
     - 不放宽任何现有 Stage Gate 规则；
     - 对由于毛利或合规暂缓（`HOLD`）但需要战略小批测试的商品，提供结构化的“商业放行审批单”与审计留存机制。
- **预期实施范围**：
  新建 `ozon-react/src/components/reports/FactorySelectionCard.jsx`，新增 `ozon-react/src/utils/marketReport/reportCandidateBridge.js`，扩展 `ozon-react/src/utils/t6/candidateProjectEvidence.js`。
- **用户收益**：
  市场报告不再是孤立的看图页面，可以直接为国内合作工厂筛选出具体规格、可发快递、有明确对标链接的测试商品，实现跨境选品小闭环。

### 切片 3 (P2)：导入恢复机制、按需轻量索引与多端体验优化
- **优先级**：**P2（中，提升系统稳健性与操作流畅度）**
- **核心目标**：
  1. 根除 `O(N)` 全量并行下载风暴：
     - 将报告列表改为两层加载架构：首屏仅获取轻量元数据摘要（Summary List: `id`, `label`, `snapshot`, `rowCount`, `publishedAt`）；
     - 仅当用户点击某份报告时，再按需请求该报告的完整数据 JSON；
  2. 孤儿源文件检测与恢复机制：
     - 在报告中心增加“未发布源文件管理”抽屉，检测 `market-report-sources` 中已备份但未生成报告的孤儿文件，支持一键“重试生成报告”；
  3. 移动端与长列表自适应：
     - 为长表格提供移动端折叠卡片（Card Layout），解决小屏下反复大面积横向滑动的体验痛点。
- **预期实施范围**：
  `MarketReportCenter.jsx`、`UploadedMarketReport.jsx`、`serverFiles.js`。
- **用户收益**：
  即使积累上百份报告，页面依然秒开；网络故障时数据不丢不卡，移动端现场看选品卡体验更佳。

## 三、明确不做项（Non-Goals / Out-of-Scope）

为确保聚焦于 2-3 人跨境运营团队的实际需求并控制变更风险，以下内容明确**不在**后续实施范围内：

1. **不做多租户 SaaS 权限与复杂 RBAC 系统**：
   - 团队规模仅为 2-3 名内部核心成员，当前基于 WordPress Secret/Cookie 的基础访问控制已完全满足需求，坚决不引入复杂的组织架构、权限组和 OAuth 体系。
2. **不做自动爬虫系统与第三方 API 直连**：
   - 坚持以用户从 Ozon 卖家中心合规导出的原生 Excel/CSV 为唯一事实源，不引入高维护成本且易被风控的自动化爬虫程序。
3. **不做 Git 历史中的公开数据清洗（TD-19）**：
   - 仓库历史中留存的测试 xlsx/json 属于数据治理议题，需要执行重写历史并 force-push，该操作具有破坏性，必须单独立项并获得用户单独授权，严禁随业务切片顺带执行。
4. **不做运费公式、毛利率引擎及合规法规逻辑的任何放宽修改**：
   - `wbEngine.js`、`ozonEngine.js`、`wb_calc.py` 以及 EAC/GOST 合规判断是系统的最高守卫准则，任何切片中严禁顺手“优化”或放宽计算标准。
5. **不做脱离实际性能指标的臆想优化**：
   - 所有性能改善必须基于实际测量或物理请求数（如 `O(N)` 降为 `O(1)`），不宣称未经测量的“提速百分比”。
