# Kuajing 本地 AI 交接入口

## 角色与执行方式

- 用户决定业务目标及生产部署授权。
- Codex 写任务书、冻结范围、独立验收、决定返工及下一任务。
- Gemini 读取当前任务，执行允许范围，提交结果报告及下一步建议。
- Gemini 的结果报告不是下一任务的自动授权；不得自行扩大范围或部署。
- 本目录是文件交接，不是后台扫描器。用户在 Gemini 中启动执行；完成后在 Codex 说“读取本地交接并验收”。没有另外建立定时任务。

## 每轮入口

1. 读取仓库 `AGENTS.md` 及 `docs/ai-handoff/CURRENT_TASK.json`。
2. 读取指针中的 `task_file`，先检查当前代码与基线是否一致。
3. 状态为 `ready` 或 `revision_required` 才能领取；填写 `claimed_by` 并置为 `running`。已有执行者时不要重复执行。
4. 开始前记录 HEAD、相关工作区差异及目标文件副本。仓库已有大量未提交/未跟踪文件，不得清理、还原或归为本轮成果。
5. 严格执行任务，完成后写 `RESULT.md` 与 `tests.json`，把状态改为 `review_ready`；阻塞则写明原因并置为 `blocked`，不得伪造通过。
6. Codex 验收后写验收报告，状态改为 `accepted` 或 `revision_required`；核心范围通过但存在明确非阻断后续项时，可用 `accepted_with_known_limitations`，必须逐项记录限制、后续任务和部署门。通过后，把旧任务状态保存在其目录的 STATUS.json，再创建下一份任务书并更新唯一当前指针。

## 文件约定

所有指针路径相对仓库根目录。每个任务单独目录，包含：

- `TASK.md`：目标、允许范围、禁止事项、验收与回滚要求；执行者不可自行修改合同。
- `RESULT.md`：执行者报告，参考下方模板。
- `tests.json`：实际测试命令、退出码、结论、证据位置、未执行原因。
- `REVIEW.md`：Codex 独立验收记录。
- `evidence/`：本轮截图、精简测试日志、变更前副本及本轮增量差异。不得包含凭据或真实业务隐私。

指针中的执行状态与部署状态分开。本地测试通过不等于已部署、已发布或已公开验证。

## RESULT.md 必填模板

```markdown
# 执行结果
任务 ID：
状态：review_ready / blocked
基线 HEAD / 实际开始 HEAD：
执行范围与开始前已有改动：

## 实际完成
逐项对应 TASK.md，不使用笼统“全部完成”。

## 改动文件
每个文件写用途；说明本轮增量与执行前已有改动的区别。

## 验证
复现步骤、修复后的行为、真实测试输出和截图路径。
明确哪些只有静态检查，哪些经过运行时/浏览器验证。

## 未完成与风险
没有就写“无已知项”，不要隐瞒未跑的验证。

## 回滚
列出本轮变更前副本、增量 diff、恢复步骤。
禁止还原执行前已有改动。

## 部署
本任务未部署，未操作生产。

## 下一步建议（非授权）
建议目标、依赖、范围，等待 Codex 裁决。
```

`tests.json` 格式：

```json
{
  "task_id": "任务ID",
  "checks": [
    {"name": "检查名称", "command": "实际命令或手动步骤", "status": "passed|failed|not_run", "exit_code": null, "evidence": "相对路径", "notes": "限制或未执行原因"}
  ]
}
```

## 后续候选顺序（尚未放行）

1. 合规表单输入保护及标题按钮布局已按限定范围验收，已知限制见对应 REVIEW.md 与 BACKLOG.md。
2. 认证适用性合同修订（003 已放行，仅文档）：Store 变化字段、旧项目默认值兼容、判断依据、计划与上架放行区分。
3. 第二步合同验收后再实施认证适用性；新增测试接入默认部署检查。
4. 本机保存、服务器确认、冲突备份、恢复实测的端到端检查。

不改利润公式，不覆盖其他 AI 的工作，不把市场线索自动变成法规结论。
